# Release notes templates

## In-app "what's new"

```markdown
**New: [Feature name]**
[One sentence: what you can now do and why it helps.]

**Improved: [Area]**
[One sentence: what got better.]

**Fixed**
- [User-visible bug fixed, in plain language]
```

## Changelog / blog page

```markdown
# [Month Year] product updates

## [Theme 1]
[1-2 sentences of context.]
- [Benefit-first bullet]
- [Benefit-first bullet]

## [Theme 2]
- [Benefit-first bullet]

## Fixed
- [Bug fix in plain language]
```

## Customer email / announcement

```markdown
Subject: [Single biggest benefit, not the feature name]

Hi [name],

[Why this matters to them — 1-2 sentences.]

[What changed — 2-3 sentences, benefit-first.]

[How to try it — link or steps.]

[Support link if questions.]
```

## API / developer changelog (Keep a Changelog style)

```markdown
## [1.4.0] - 2026-08-25

### Added
- [New endpoint or field, with a one-line use case]

### Changed
- [Behavior change — call out if it's backward compatible]

### Deprecated
- [What's deprecated, removal timeline, migration path]

### Removed
- [What's gone, since which version it was deprecated]

### Fixed
- [Bug fix affecting API consumers]

### Security
- [Security-relevant fix, without exploit details]
```
